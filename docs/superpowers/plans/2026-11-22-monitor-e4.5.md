# Monitor — E4.5 (Alertas de uso + umbral de temperatura configurable) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Alertas de uso para RAM y VRAM (umbral 85/90/95 %, default 90) y umbral de alerta de temperatura configurable (70/75/80 °C, default 75) desacoplado del color de severidad. Instalar 0.1.2 para cerrar el gap repo↔instalado.

**Architecture:** Política de uso pura y testeada (rising-edge + latch, misma semántica que las temps) en un header nuevo; el preset de temp cambia SOLO la alerta (warn=preset, crit=preset+10), el color sigue en D11 (80/90). Settings: `UsageAlerts` (default ON), `UsageAlertThreshold` (default 90), `TempAlertThreshold` (default 75). Todo en el submenú System metrics (IDs 156-162, zona libre).

**Tech Stack:** C++17/Win32, MinGW-w64 (`$env:MSYSTEM='MINGW64'` antes de `bash -lc`).

**Spec:** `docs/monitor-spec.md` (E4) + este pase.

## Global Constraints

- **Umbrales**: uso RAM/VRAM default **90 %** (opciones 85/90/95); temp CPU/GPU default **75 °C** (opciones 70/75/80), crit = preset+10. SSD sin cambios (warn 65, latchea silencioso en idle).
- **Colores intactos** (D11 80/90): el preset de alerta NO altera `SeverityFor`/Layout.
- Política de uso: rising-edge, latch por métrica, **primera muestra ya sobre el umbral = latch silencioso**, reset al bajar 5 puntos (`< threshold - 5`); `ok=false` no notifica ni resetea.
- Toggles: `UsageAlerts` default ON; `Temperature alerts` existente sigue (default ON). Presets persistidos como REG_DWORD.
- Globos con el mecanismo existente; i18n: claves nuevas + es con placeholders intactos.
- Sin cambios en: bandeja, sampler, installer script (solo versión), updater. El helper no se rebuildear (lock elevado).
